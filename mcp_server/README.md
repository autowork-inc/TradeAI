# TradeAI Risk Analyst — локальный MCP-сервер

Аналитический слой поверх PostgreSQL Shadow Mode. Только математика и логи исполнения из БД — никаких соцсетей и внешних данных.
Сервер работает **на вашем ПК** (stdio), к БД на VPS подключается **только на чтение** через SSH-туннель. На VPS ничего не деплоится.

| Инструмент | Что делает |
|---|---|
| `get_strategies_overview(time_window_hours=168)` | По каждому `strategy_id` за окно: число сделок, Win Rate, Profit Factor, Net R, средний R ± ошибка, лучшая/худшая монета; сколько сделок окна в статистику не вошло (открытые, отменённые, `aborted`, `gap_affected`) |
| `get_trade_details(strategy_id, limit=20)` | Последние сделки (новые первыми, до 100): цены, SL/TP, PnL, net R, MFE/MAE, причина выхода, все частичные закрытия, **текст причины входа** (`reason`), **HTF Bias H4**, сырые параметры сигнала (`signal_meta`) |
| `analyze_drawdown_causes(strategy_id, worst_trades_limit=15)` | Убыточные сделки (Net R < 0) против всех закрытых: макс. просадка в R с датами пика и дна, профиль убытков (как быстро цена шла против входа), разбивки по **HTF Bias / по тренду (`with_trend`, `counter_trend`) / стороне / монете / причине выхода / часу UTC** (+ по сессии для `ICT_Killzones`, по подтверждению OBI/дельта для `OBI_Breakout`) с долей каждой группы в общем убытке, худшие сделки с текстом причины входа |

Стратегии: `SMC_Pro_Trend`, `SMC_Counter_Trend`, `OBI_Breakout`, `ICT_Killzones`, `VWAP_Reversion` (старые сделки — `smc`, `breakout`). Неверное имя → ответ перечисляет известные `strategy_id` из БД.

**Как считается.** Сделка в статистике = `status = 'closed'` и не `gap_affected`, режим `shadow` — те же определения, что в `api/stats.py` и `deploy/shadow.sh stats`. Net R = `trades.r_multiple` (с комиссиями, со всеми частичными закрытиями). Win Rate — доля Net R > 0. Profit Factor — прибыль R / модуль убытка R. Пока сделок меньше 200, в ответе есть `sample_warning`: **это описание, а не вывод о прибыльности** (разброс одной сделки ≈ 1.4 R), группы меньше ~20 сделок — шум.

> **Про поле `reason`.** В таблице `trade_snapshots` колонки `reason` нет: там `candles`, `geometry`, `meta` (JSONB). Текст причины входа строит функция `api/reason.py::build_reason` из `meta` и геометрии — тот же код, что показывает клиент. Сервер импортирует её из репозитория (папка `api/` рядом с `mcp_server/`). Если `mcp_server/` скопирован отдельно — текста `reason` не будет, останутся `htf_bias` и сырой `signal_meta`.

## 1. Что нужно для доступа к БД на VPS

База `tradeai` работает в контейнере `postgres` и **наружу порт не публикуется** (это сознательное решение проекта: `docker-compose.yml`, тест `test_deploy`). Открывать 5432 в интернет не надо. Вам нужно:

1. **SSH-доступ к VPS** (`193.233.75.254`) **по ключу** (с 2026-10-12 настроен: `~/.ssh/id_ed25519` без парольной фразы, публичная часть в `/root/.ssh/authorized_keys`; проверка: `ssh -o BatchMode=yes root@193.233.75.254 "echo OK"`). На Windows 10/11 клиент `ssh` встроен.
2. **Право запускать `docker` на сервере** под этим пользователем (скрипт туннеля выполняет только `docker ps` и `docker inspect`; запись на сервере не происходит).
3. **Пароль БД** — `POSTGRES_PASSWORD` из `~/trading/.env.shadow` на сервере:
   ```bash
   ssh root@193.233.75.254 "grep POSTGRES_PASSWORD ~/trading/.env.shadow"
   ```
   Пароль — латиница и цифры, поэтому в `DATABASE_URL` экранировать нечего.

### Туннель: по ключу и автоматически (с 2026-10-12)

Пароль не нужен нигде. `tunnel.ps1` входит по ключу `~/.ssh/id_ed25519` (`BatchMode` — запроса пароля быть не может), при **каждом** подключении заново узнаёт внутренний адрес контейнера `postgres` (он меняется при пересоздании контейнера; на сервере выполняются только `docker ps` и `docker inspect`), открывает `127.0.0.1:15432` → `postgres:5432` и **сам переподключается** через 10 с, если связь оборвалась (сеть, сон/пробуждение ПК, перезагрузка VPS). Вторая копия сразу завершается (мьютекс). Лог — `mcp_server\tunnel.log`.

| Что | Как |
|---|---|
| **Автозапуск при входе в Windows** (один раз) | `.\mcp_server\install_autostart.ps1` — создаёт задачу Планировщика «TradeAI MCP Tunnel» (триггер — вход вашего пользователя, без прав администратора, без окна консоли), сразу её запускает |
| **Запуск в один клик** | двойной клик по `mcp_server\tunnel-hidden.vbs` — тихо, без чёрного окна (безопасно нажимать повторно) |
| **Вручную в консоли** (видно лог) | `.\mcp_server\tunnel.ps1` (параметры по умолчанию: `-SshHost 193.233.75.254 -User root -LocalPort 15432 -KeyFile ~/.ssh/id_ed25519`) |
| **Остановить / убрать автозапуск** | `.\mcp_server\install_autostart.ps1 -Uninstall` |
| **Проверить, что работает** | `Get-Content mcp_server\tunnel.log -Tail 5` и `Get-NetTCPConnection -LocalPort 15432 -State Listen` |

Триггер именно «вход пользователя», а не «запуск системы»: ключ лежит в вашем профиле и читается только в вашей сессии. Если пользователь на ПК другой или ключ пересоздан — повторите `install_autostart.ps1` и добавьте новый публичный ключ (`~/.ssh/id_ed25519.pub`) в `/root/.ssh/authorized_keys` на сервере.

**Ключ на ПК = доступ root к VPS.** Файл `~/.ssh/id_ed25519` (без парольной фразы) нельзя копировать, отправлять и коммитить; потеряли ПК — удалите его строку (комментарий `tradeai-mcp-tunnel@desktop-ok87v3k`) из `/root/.ssh/authorized_keys`. После перехода на ключи пароль root можно сменить (`passwd`) — туннель и MCP от этого не зависят.

*Запасной вариант (если не хотите искать адрес контейнера):* на сервере один раз добавить в `docker-compose.yml` сервису `postgres` строку `ports: ["127.0.0.1:5432:5432"]` (только localhost сервера, не интернет) и пересоздать контейнер; тогда туннель — обычный `ssh -N -L 15432:127.0.0.1:5432 root@193.233.75.254`. Это правка боевого compose, и она ломает проверку `test_deploy` (порт БД не публикуется) — поэтому по умолчанию я её не делаю.

## 2. Установка (один раз)

Нужен Python 3.10+. В репозитории уже создано окружение `mcp_server\.venv`; если его нет или оно сломалось:

```powershell
cd D:\softs\Trading
python -m venv mcp_server\.venv
mcp_server\.venv\Scripts\python.exe -m pip install -r mcp_server\requirements.txt
```

Строка подключения — в `mcp_server\.env` (шаблон — `mcp_server\.env.example`):

```ini
DATABASE_URL=postgresql://tradeai:ВАШ_ПАРОЛЬ@127.0.0.1:15432/tradeai
```

Из `.env` читается **только** `DATABASE_URL` (сначала `mcp_server\.env`, затем корневой `.env`; ключи Binance оттуда не берутся). Переменная окружения `DATABASE_URL`, если задана, сильнее файлов — её можно передать в блоке `env` конфигурации MCP (см. ниже) вместо файла.

Проверка без клиента (туннель должен быть поднят):

```powershell
mcp_server\.venv\Scripts\python.exe -c "import asyncio, sys; sys.path.insert(0,'mcp_server'); import server; print(asyncio.run(server.get_strategies_overview(168)))"
```

## 3. Подключение к Cursor

Файл `%USERPROFILE%\.cursor\mcp.json` (для всех проектов) или `D:\softs\Trading\.cursor\mcp.json` (только этот проект), либо *Settings → MCP → Add new MCP server*:

```json
{
  "mcpServers": {
    "tradeai-risk": {
      "command": "D:\\softs\\Trading\\mcp_server\\.venv\\Scripts\\python.exe",
      "args": ["D:\\softs\\Trading\\mcp_server\\server.py"]
    }
  }
}
```

Пароль не в файле, а в конфиге — вариант без `.env`:

```json
"env": { "DATABASE_URL": "postgresql://tradeai:ВАШ_ПАРОЛЬ@127.0.0.1:15432/tradeai" }
```

После сохранения в *Settings → MCP* у `tradeai-risk` должна гореть зелёная точка и три инструмента. Красная — смотрите лог (кнопка Show Output): сервер пишет только в stderr.

## 5. Примеры запросов в чате

- «Дай сводку по всем стратегиям за последние 72 часа и скажи, где выборка слишком мала».
- «Разбери причины убытков SMC_Pro_Trend: влияет ли HTF Bias и торговля против тренда H4?»
- «Покажи последние 10 сделок ICT_Killzones с причиной входа; есть ли общее у стопов?»
- «Сравни `by_hour_utc` и `by_session` убытков у ICT_Killzones».

Что сервер **не** делает: не выдаёт торговых рекомендаций и не пишет в БД. Выводы о прибыльности допустимы только при сотнях сделок (CLAUDE.md, разд. 3.11.1) — модель получает `sample_warning` в каждом ответе.

## 6. Безопасность

- **Только чтение, три независимых слоя:** (1) сессия БД открыта с `default_transaction_read_only = on` — сервер Postgres сам отклонит INSERT/UPDATE/DELETE/DDL (проверено тестом на настоящей БД); (2) `Database.fetch()` пропускает ровно один оператор, начинающийся с `SELECT`/`WITH`, без `;`; (3) все запросы — готовые строки в `queries.py` с параметрами `$n`, текст от LLM в SQL не подставляется (`strategy_id` дополнительно проверяется по `^[A-Za-z0-9_.-]{1,64}$`, числа — по диапазонам).
- Таймаут запроса 25 с, пул до 3 соединений, окно ≤ 8760 ч, `limit` ≤ 100.
- Пароль не попадает в сообщения об ошибках и логи; в `trade_snapshots` читаются только `meta` и `geometry` (без свечей).
- Роль БД та же, что у остальных сервисов (`tradeai`); отдельной роли «только SELECT» нет (О32) — защита держится на пунктах выше. `.env` лежит в `mcp_server/`; он перечислен в `mcp_server/.gitignore`, а папка исключена из `.dockerignore` и архива `deploy_pack`.
- Сервер не слушает порт: общается с клиентом MCP через stdin/stdout.

## 7. Ошибки соединения

Инструмент возвращает понятное сообщение (без пароля), а не падает; сервер при этом остаётся живым:

| Сообщение | Причина | Что делать |
|---|---|---|
| `DATABASE_URL не задан` | нет `mcp_server\.env` и переменной | создать по `.env.example` |
| `Нет доступа к БД 127.0.0.1:15432/tradeai: нет соединения: SSH-туннель не поднят…` | туннель не запущен/оборвался, неверный порт | проверьте `tunnel.log`; запустите `tunnel-hidden.vbs` (или `install_autostart.ps1`); порт в `DATABASE_URL` = `-LocalPort` |
| `…сервер БД отклонил логин/пароль…` | пароль не тот | взять `POSTGRES_PASSWORD` с сервера (разд. 1) |
| `Соединение с БД потеряно…` | туннель оборвался посреди работы | туннель переподключится сам за ~10–30 с; повторите вызов — пул пересоздастся сам |
| `Таблицы нет: схема БД не создана или старше v2` | на VPS не запущен shadow-run после обновления | `./deploy/shadow.sh up` на сервере |
| `Запрос отменён по таймауту` | слишком широкое окно/медленный канал | сузить окно |

$env:TEST_DATABASE_URL = "postgresql://tradeai:pw@127.0.0.1:54331/tradeai_test"          # БД *_test, схема public ПЕРЕСОЗДАЁТСЯ

Тесты с БД поднимают схему из `persistence/schema.py` (миграции v1–v2) и засевают сделки, поэтому запускаются из репозитория.

## Файлы

| Файл | Роль |
|---|---|
| `server.py` | MCP-сервер (FastMCP, stdio), три инструмента, валидация аргументов |
| `db.py` | чтение `DATABASE_URL`, ленивый пул asyncpg только на чтение, защита запросов, ошибки без пароля |
| `queries.py` | все SQL (только `SELECT`, параметры `$n`) |
| `analytics.py` | чистая аналитика (метрики, просадка, разбивки), текст причины входа через `api.reason` |
| `tunnel.ps1` | SSH-туннель до PostgreSQL на VPS: по ключу, с автопереподключением и логом |
| `tunnel-hidden.vbs` | запуск туннеля без окна консоли (в один клик) |
| `install_autostart.ps1` | регистрация/удаление задачи Планировщика «TradeAI MCP Tunnel» (автозапуск при входе) |
| `.env.example`, `requirements.txt` | шаблон настроек, зависимости (`mcp>=1.9,<2`, `asyncpg`) |
| `tests/test_mcp_server.py` | 28 тестов |
